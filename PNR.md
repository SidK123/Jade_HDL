# Simulated Annealing
Probabilistic algorithm, apparently is named after the metallurgical process of annealing where metal is heated up a lot, and then allowed to cool to settle the atoms in their lowest-energy state. The idea here is that we choose an initial configuration for the cells, and make small movements and see if some global cost is reduced. If it is, then we accept it with 100% probability and even if it isn't, we accept it with some probability that's a function of our "temperature", and the time that has elapsed. The idea here is that we avoid settling into a local cost minimum, and instead we allow, especially in the beginning, locally suboptimal moves to hopefully achieve a global minima. Tempeerature is pretty similar to alpha in RL I think. Will be slow and CPU intensive, though.
# Min-Cut Algorithm
If you think of a circuit as a set of elements (LUTs, DSP blocks, etc.) connected by a set of signals, our placement problem becomes: can we place our elements such that the total distance spanned by the routes necessary to connect one net is minimized? This can be turned into the min-cut problem. Consider partitioning your FPGA/ASIC space with horizontal and vertical lines, and trying to find an objective function that minimizes the number of signals that are 'cut' by our horizontal and vertical lines. Intuitively, this makes sense. We would want our signals connecting nets across elements to be localized within a pretty small area, so that we don't incur crazy routing delay. By minimizing our cut value, we minimize routing delay.
